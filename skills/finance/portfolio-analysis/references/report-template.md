# Markdown report contract

Write a readable `portfolio-report.md`; adapt depth to evidence and portfolio
complexity. Resolve all sections, using explicit unknown/not-applicable statements
where needed. No unfinished placeholders. Use Markdown tables where useful in the
file; the requested deliverable is a standalone Markdown report.

1. **Summary and report status.** Full or limited review, major strengths/risks,
   highest-value next actions and what cannot yet be concluded. State holdings
   valuation date, research cutoff and investor-context completeness immediately.
2. **Scope, evidence and reconciliation.** Source filename/hash, masked accounts,
   statement periods/base currencies, export completeness, ignored/unsupported
   records, ending NAV/cash/securities and residual. Link workpaper and JSON.
3. **Portfolio state.** Confirmed holdings, quantities, prices/value dates,
   currencies, weights with denominator, cash and gross/net exposure. Keep
   activity-only observations in a separate subsection labeled as such.
4. **Diversification and risk.** Asset class, sector, geography, currencies,
   issuer concentration, fund overlap, liquidity and leverage. Show unknown
   portions. Explain look-through source dates and material portfolio gaps.
5. **Holding reviews.** Each holding's role, verified instrument type, thesis,
   valuation/quality or fund structure, key risks, action, confidence and source
   links. Link full company reports and dated fund evidence. Record skipped
   analytical coverage explicitly.
6. **Additions, reductions and alternatives.** Evidence-backed candidates to
   add/trim/exit/hold/research first, why they improve the whole portfolio,
   counterarguments, costs and conditions. Include a no-action alternative.
7. **Allocation and implementation.** Current versus conditional/selected target
   ranges, rationale, contribution-first plan, feasibility, friction and liquidity.
   With missing holdings/context give scenarios, not exact trade quantities.
8. **Stress and performance.** Supported illustrative shocks and assumptions;
   actual return metrics only when data supports them. State missing history.
9. **Open questions and review triggers.** Prioritize information that can change
   a decision; distinguish thesis events from a suggested review cadence.
10. **Sources and audit trail.** Link the resolved universe, scraper CSV/manifest,
    filing/fund URLs, analysis reports and scenario inputs. Cite material claims
    inline as well, with publication/valuation dates where consequential.

Before delivery verify: numerical totals/currencies/dates reconcile; weights do
not disguise unknown exposures; no trading activity is called holdings; target
ranges are feasible; historical evidence obeys cutoff; sources support claims;
recommendations distinguish facts, derived values, assumptions and judgment.
An incomplete but useful report must label its limits and explain how they change
the proposed actions, not bury them in a generic disclaimer.
